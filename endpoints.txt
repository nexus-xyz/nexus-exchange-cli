# Spec operations the CLI's commands exercise, checked against the pinned spec
# (.api-version) by scripts/check_spec_drift.py. This is the CLI counterpart to
# the same-named file in the Rust SDK (nexus-exchange-rs): it turns the
# dashboard's CLI API-coverage panel from "no data" into a real percentage.
#
# The check validates this file BOTH ways:
#   * every line must exist in the pinned spec (no removed/renamed/typo'd op);
#   * the set must equal the SDK methods the CLI actually calls (parsed from
#     src/main.rs and src/wsclient.rs and mapped to spec ops via METHOD_OP in
#     check_spec_drift.py), modulo ONE documented allowlist in that script:
#       - NON_REST_TARGETS — exercised without a named REST method call; e.g.
#         GET /ws (the WebSocket upgrade, opened by the streaming client, not a
#         `client.<method>()` REST call).
#
# There is no allowlist for the other direction any more. CODE_ONLY_OPS was one:
# a command could call an SDK method for an op absent from the pinned spec and be
# kept out of this file, on the claim that the spec would catch up. It never did
# for any of the nine rows that accumulated there (account leverage,
# funding-payments, transfers, sub-accounts, batch cancel, the two by-client-id
# ops), so the commands shipped as dead ends under a green gate. They were
# deleted in ENG-12369 and the table is now sealed empty (ENG-8616): an operation
# the pinned spec does not define is not implemented, and ANY entry fails the
# check. When a PUBLISHED spec version defines an op, the command is implemented
# against that version and the line is added HERE, covered rather than exempted.
#
# So: add a line here whenever a CLI command starts exercising a new spec op (a
# new `client.<method>()` call mapped in METHOD_OP), or the drift check fails.
# Format:  METHOD /path   (placeholders match the spec, e.g. {market_id})
#
# ── /api/v1 migration (ENG-4949, parent ENG-4740) ──────────────────────────────
# The gateway REST proxy is being eliminated: each backend service now exposes
# its own REST API under the host-root `/api/v1` prefix. This move is DUAL-STACK
# (ENG-4751) — the legacy `/api/exchange` gateway paths stay live, so operations
# that do NOT yet have an `/api/v1` variant remain on the bare gateway path.
#
# Which op lands where is decided in the SDK, not here: the CLI is a thin layer
# over `nexus-exchange`, and the regenerated SDK (ENG-4947, nexus-exchange-rs
# PR #85) selects the base per request off the `/api/v1/` path prefix. The lines
# below mirror that SDK routing exactly — `/api/v1/...` for the migrated ops, the
# bare gateway path for the rest. Runtime routing flips only when this crate bumps
# its `nexus-exchange` dependency to the regenerated SDK release (ENG-4947); this
# file and the drift check are the spec-coverage bookkeeping that goes with it.
#
# Commands that DON'T appear here, by design: `setup` and `completions` are
# local-only (no API call).
#
# `auth login` and `agents register` used to be listed here as a third exclusion,
# on the grounds that a wallet-signed request was "covered by the SDK's own
# coverage file, not this one". That was never true — they are ordinary spec
# operations the CLI calls — and because their SDK methods had no METHOD_OP row,
# nothing could contradict it. They are listed below, and invariant 9 now fails a
# call the mapping does not carry (ENG-12786).
